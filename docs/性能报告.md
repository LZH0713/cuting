# Cuting 性能报告

> 测试环境：Apple Silicon Mac（内建屏 1512×982 @2x + 外接屏），macOS 15.0
> 数据来源：应用自身日志（`~/Library/Logs/Cuting/app.log`）与自动化自测（`src-tauri/src/selftest.rs`），
> 每次截图/识别都会记录耗时，可随时复核。
> 报告日期：2026-11-27 · 对应版本 v0.2.0（标注工具 + 长截图 + 性能优化）

## 1. 核心耗时实测（本机双屏）

以下为真实使用场景的采样（v0.2.0 发布日累计 58 次联合抓屏）：

| 阶段 | 实测值 | 说明 |
|---|---|---|
| 双屏联合抓屏（ScreenCaptureKit） | **147 – 519 ms**，典型 **165 – 260 ms** | 含两块屏的 SCK 采集 + 8144×5120 合成帧拼装 |
| 单屏抓屏 | **32 – 120 ms** | 内建屏 @2x，3024×1964 像素 |
| 选区 OCR（Vision，本机） | **306 – 415 ms**，典型 **≈ 350 ms** | 2~10 行文字区域，精确模式（日志带级别标注） |
| OCR 全链路（点击「提取文字」→ 结果窗） | **约 1 s** | 含裁剪、识别、预览图编码、结果窗就位 |
| 复制到剪贴板（点击 → 完成） | **< 15 ms**（日志 6 ms 间隔） | 含标注层合成（内存像素叠加，不单独计时） |
| 冷启动（launch → 托盘可用） | **≈ 365 ms** 进程拉起，**≈ 2 s** 两块屏覆盖层预热完成 | 覆盖层窗口预热常驻，热键触发无冷启动 |
| 热键 → 覆盖层呈现（热路径） | **< 200 ms** | 抓屏 165 ms + 窗口呈现 |
| 长截图单次滚动拼接 | 每帧一次区域抓屏 + 偏移匹配，滚动中实时增长 | 拼接高度实测连续增长至 15000+ px 无失败 |

数据源样例（`app.log`，v0.2.0 起 OCR 日志带识别级别）：

```
display 1 captured in 50 ms
display 3 captured in 65 ms
captured 2 display(s) in 238 ms
ocr: 2 line(s) in 332 ms (Accurate)
ocr: 10 line(s) in 415 ms (Accurate)
copied 1439x1584 px (719.5 pt) to the clipboard
```

## 2. 资源占用（空闲常驻态）

| 项目 | 实测值 |
|---|---|
| 安装包（.app） | **9 MB**（zip 分发 4.3 MB） |
| 主进程 RSS（空闲，OCR 预热完成 + 双屏覆盖层已预热） | ≈ **188 MB** |
| 覆盖层 WebContent ×2（每屏一个，预热常驻） | 合计 ≈ **83 MB** |
| WebKit GPU / Networking 助手 | ≈ 22 / 6 MB |
| 全部相关进程合计 | **≈ 290 MB** |
| 空闲 CPU | **0%**（10 秒采样；抓屏/OCR 均为亚秒级突发） |

> 说明：主进程 188 MB 的大头是启动时预热的 OCR/Vision 管线；两个常驻
> WebView 是"热键即出、无冷启动"的代价。资源敏感场景可在后续版本中
> 把 OCR 预热改为懒加载（首次识别略慢）或覆盖层空闲释放（Ctrl+A 变冷启动，
> 不建议——页面加载链路对冷启动敏感）。

## 3. 与同类产品的性能对比

> ⚠️ 数据口径说明：同类产品（闭源）没有公开的逐项性能基准，下表中它们的
> 数据来自官方安装包体积、社区测评与用户反馈（见文末链接），为**定性或
> 数量级参考**；Cuting 一行为本机实测。

| 指标 | Cuting (实测) | Shottr | PixPin | iShot | Snipaste | CleanShot X | macOS 原生 |
|---|---|---|---|---|---|---|---|
| 安装包体积 | **9 MB**（zip 4.3 MB） | ≈ 5 MB（社区口径：轻量） | ≈ 30–60 MB | ≈ 30+ MB | ≈ 20 MB | ≈ 50+ MB | 系统内置 |
| 双屏联合抓屏 | **165–260 ms** | 未公开基准 | 未公开基准 | 未公开基准 | 未公开基准 | 未公开基准 | 未公开基准 |
| OCR 引擎 | **Vision 本机**（离线） | Vision 本机（离线） | 部分离线 + 云 | 云/本机混合 | ✘ | 本机(离线) | ✘（无 OCR） |
| OCR 中文识别耗时（本机实测口径） | **306–415 ms** | 同级（Vision） | 云往返为主 | 云往返为主 | — | 同级（Vision） | — |
| 常驻内存（多屏预热） | ≈ 290 MB（含 WebView） | 社区公认最轻量 | 中等 | 中等 | 轻量 | 中等 | 极轻 |
| 空闲 CPU | **0%** | 极低 | 低 | 低 | 极低 | 低 | 无 |
| 更新 | **应用内 + minisign 签名校验** | 应用内 | 应用内 | App Store | 应用内 | 应用内 | 系统更新 |

**要点解读**：

1. **抓屏延迟**：ScreenCaptureKit 是 Apple 当前推荐的采集通道，本机双屏
   165–260 ms 的表现处于该通道的合理区间；Shottr 等原生工具使用私有的
   CGWindowList 旧通道，社区反馈速度相近。
2. **OCR**：Cuting 与 Shottr、CleanShot X 同样走 Vision 离线识别，
   隐私与延迟优于云 OCR；PixPin 部分高级 OCR 为会员云服务。
3. **内存**：Cuting 因每屏常驻一个 WebView + 启动预热 OCR，空闲内存高于
   原生工具（Shottr 最轻）；这是"热键即出、OCR 即用"的代价，属于
   Tauri/WebKit 应用的典型水平。

## 4. 压力与边界行为

| 场景 | 表现 |
|---|---|
| 双屏 + 混合缩放（2x/1x） | 每屏独立 WebView，缩放/坐标正确（联合 WebView 方案在混合缩放下有 WebKit 已知错位问题，已弃用） |
| 跨屏拖选 | 选区矩形经 Rust 以桌面坐标广播，各屏绘制自己的交集部分；标注/长截图要求单屏内选区，越界时明确提示 |
| 系统 Vision accurate 降级 | 实测本机 accurate 级别慢至 29.7 s 时：15 s 自动降级 fast 级别（0.08 s），**用户实际全链路 348 ms**；20/40 秒两级超时兜底，不会永久转圈 |
| 大图复制 | 2395×7088 长截图复制有崩溃保护 + panic 钩子记录（问题记录于调试日志） |
| 更新包完整性 | minisign 签名校验，拒绝非发布方的更新包 |

## 5. 复核方式

```sh
# 抓屏/OCR 耗时
tail -f ~/Library/Logs/Cuting/app.log | grep -E 'captured|ocr:'

# 界面自动化自测（含全链路计时）
CUTING_SELFTEST_OUT=/tmp/cuting-selftest \
CUTING_SELFTEST_FIXTURE="$PWD/src-tauri/target/ocr-fixture.png" \
  src-tauri/target/release/bundle/macos/Cuting.app/Contents/MacOS/cuting

# 单元测试
npm run test
```
